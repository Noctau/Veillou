# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Версии — по вехам плана разработки.

## [Unreleased] — аудит безопасности и качества

Подробности и статус каждой находки — [AUDIT_REPORT.md](AUDIT_REPORT.md).

### Security
- Ограничение перебора пароля по адресу и аккаунту (429 + `Retry-After`); argon2 в потоке,
  не больше двух проверок одновременно; длина пароля ≤ 1024 (H-01).
- Лимит тела запроса до аутентификации и разбора: ASGI-middleware и Caddy по путям (M-01).
- Push-подписки — только на известные push-сервисы, без редиректов (SSRF, M-02).
- Выход отписывает устройство от push (M-03).
- ReDoS в выдержке конспекта (M-04); «невозможные» RRULE отклоняются, проверка — в потоке (L-01).
- Квота ИИ-запросов на пользователя (M-05).
- Строгий CSP, `frame-ancestors`, `Permissions-Policy` для страниц приложения (L-07);
  Caddy работает не от root (L-11).
- Пароль БД не попадает в `repr(settings)` (L-08); `SECRET_KEY` в проде ≥ 32 символов (L-09);
  смена пароля закрывает сессии, старые сессии чистятся (L-10).
- Подпись ссылок на файлы не пишется в access-лог (I-04); `?next=` после входа строже (I-08).
- Базовые образы по digest, сборка с `--pull`, Dependabot (M-10); `katex` без CVE (L-12).

### Fixed
- Сборка фронта с чистого клона (без `openapi.json`) (H-02).
- Двойное нажатие: применение плана, кнопки напоминаний, карточки бота, «Запланировать»,
  «Сохранить» этапы, «Начать» — выполняются один раз (M-06, M-07).
- Длинные сообщения обрезаются под лимиты Telegram и Web Push (M-08).
- Границы дат и длительностей: без `OverflowError` и сотен тысяч вхождений (M-09).
- Гонки upsert → 409 вместо 500 (L-02); ошибка одного пользователя не останавливает ночные
  задачи для остальных (L-03); постоянные 4xx от LLM не ждут 72 часа (L-04); «ядовитая»
  джоба не перезахватывается бесконечно (L-05); огромные фото не читаются в память (L-06).
- Неподходящее действие на напоминании — 409, а не «на завтра» (I-07).

### Changed
- Единый формат ошибок API `{"error": {"code", "message"}}` для 404/405/413/422/429/500 (L-14).
- `mypy --strict` без ошибок; расширенный набор правил ruff (L-15); `assert` в коде заменены
  явными проверками (L-16).
- Healthcheck воркера и бота по heartbeat, корректная остановка воркера по SIGTERM (L-19);
  fail-fast проверка конфигурации (L-20).

### Added
- Тесты фронтенда (Vitest), конфигурация coverage с порогом, тесты воркера (M-11, L-21).
- CI: mypy, deptry, coverage, vitest, gitleaks, pip-audit, npm audit, bandit, trivy,
  сборка образов (M-12); pre-commit; README уровня портфолио, CHANGELOG (L-18).
