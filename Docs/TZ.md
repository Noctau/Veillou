# ТЗ: приложение-планировщик для учёбы и жизни

28 сент. 2026 г.

> Исходные хотелки заказчицы. Это не спецификация: где `CONTEXT.md` и ТЗ расходятся, прав `CONTEXT.md`.

## 1. Цель и контекст

Нужен личный помощник-планировщик: он хранит всё про учёбу, сам раскладывает задания по дням и напоминает, что делать, чтобы ничего не держать в голове.

Пользователь — одна студентка 4 курса (бакалавриат, геофак МГУ, кафедра метеорологии и климатологии). Второй пользователь (муж) с общими событиями желателен, но не срочен (этап 3), поэтому у всех данных сразу должен быть владелец (user_id).

Приоритеты по важности:
1. Учёба: расписание пар, предметы, конспекты, литература, задания с дедлайнами.
2. Планирование: задания автоматически делятся на подзадачи (с помощью ИИ) и раскладываются по свободным слотам в календаре.
3. «Долгий ящик»: список дел, которые постоянно откладываются, тоже попадает в график.
4. Личное и отдых: встречи, быт, спорт, свободное время — чтобы план был реалистичным, а не только про учёбу.
5. Напоминания: пуш на телефон и Telegram.

Главный принцип: ввод должен занимать секунды (иначе приложением перестанут пользоваться), а план должен сам перестраиваться, если что-то не успела.

## 2. Сценарии использования

Каждый сценарий ниже — критерий приёмки: если он проходит, функция готова.

1. **Утро.** В 8:00 в Telegram приходит сводка: пары на сегодня (с аудиториями), 2–4 учебные подзадачи на свободные окна, одно дело из «долгого ящика», дедлайны на неделю.
2. **Новое задание.** После пары вставляю текст задания (или фото доски) и дедлайн. ИИ предлагает подзадачи с оценкой времени, я правлю и жму «Запланировать» — подзадачи встают в свободные окна до дедлайна.
3. **Не успела.** Вечером отмечаю невыполненное. Приложение предлагает перенести его, сдвигает остальное и предупреждает, если дедлайн под угрозой.
4. **Конспекты.** Открываю предмет и вижу всё в одном месте: пары, конспекты (фото, PDF, текст), литературу, задания и дедлайны.
5. **Перед парой.** За 15 минут пуш: какая пара, где, что взять или подготовить.
6. **Долгий ящик.** Пишу боту «записаться к стоматологу» — дело падает в список. Раз в неделю приложение предлагает поставить 1–3 таких дела в свободное время.
7. **Отдых.** Отмечаю отдых и личные дела как блоки, которые планировщик не трогает; в неделе всегда остаётся свободное время.
8. **Сессия.** Добавляю экзамен и дату — приложение строит план подготовки по билетам до экзамена.

## 3. Платформа, стек и архитектура

Одно PWA-приложение (ставится на телефон с главного экрана и открывается на ноутбуке) плюс Telegram-бот; вся логика, планировщик и ИИ — на сервере.

Клиенты только показывают данные и собирают ввод; воркер отдельно от API рассылает напоминания точно в срок.

Рекомендуемый стек (окончательный выбор за разработчиком; зафиксированный — в `CONTEXT.md`):

| Компонент | Рекомендация | Зачем |
|---|---|---|
| Фронтенд | React + TypeScript + Vite, vite-plugin-pwa | PWA «из коробки», один код для телефона и ноутбука |
| Календарь в UI | FullCalendar или Schedule-X | готовые виды день / неделя / месяц, перетаскивание |
| Офлайн | IndexedDB (Dexie) + Service Worker | смотреть план и конспекты без интернета |
| Бэкенд | Node.js (NestJS или Fastify) + TypeScript; альтернатива — Python FastAPI | общие типы с фронтом |
| БД | PostgreSQL + Prisma или Drizzle | связи предметов, задач, файлов |
| Фоновые задачи | pg-boss (без Redis) или BullMQ + Redis | напоминания и ночной пересчёт плана |
| Файлы | S3-совместимое хранилище или диск VPS | фото тетрадей, PDF |
| ИИ | LLM API с JSON-ответом и поддержкой изображений | разбивка заданий, распознавание фото задания |
| Push | Web Push (VAPID), библиотека web-push | уведомления на телефон |
| Бот | grammY (Node) или aiogram (Python) | ввод и напоминания в Telegram |
| Хостинг | один VPS + Docker Compose, домен с HTTPS | HTTPS обязателен для PWA и push |

Важно:
- На iPhone push для PWA работают только после «Добавить на экран „Домой“» (iOS 16.4+). На Android — сразу в браузере.
- Провайдера LLM выбрать с учётом доступности и оплаты из России; код ИИ спрятать за одним интерфейсом, чтобы провайдера можно было сменить.
- Авторизация: одна учётная запись (email + пароль или magic link); Telegram привязывается командой `/start` с одноразовым кодом.

## 4. Функциональные требования

Одиннадцать модулей; всё, что относится к учёбе, привязано к предмету, чтобы по предмету можно было открыть всё сразу.

### 4.1. Учёба: предметы, пары, конспекты, литература

**Семестр.** Даты начала и конца, период сессии, праздники и выходные (в эти дни пары не показываются).

**Предметы.** Название, короткое имя, цвет, преподаватель(и), форма контроля (зачёт / диф. зачёт / экзамен), ссылки (чат группы, СДО, почта преподавателя).

**Расписание пар.**
- Повторяющиеся пары: день недели, номер пары или время, тип (лекция / семинар / практикум), корпус и аудитория.
- Чётность недели (числитель / знаменатель) и пары «через неделю».
- Разовые изменения: отмена, перенос, замена аудитории — без правки всей серии.
- Ввод вручную, импорт не нужен: сетка недели, копирование пары на другой день и на другую чётность.
- Настройка звонков (время каждой пары) один раз на семестр.

**Конспекты.** Привязаны к предмету и, по желанию, к конкретной паре (дате).
- Текст: Markdown-редактор с формулами LaTeX (нужны для физики атмосферы и математики).
- Фото тетради: несколько страниц одним конспектом, съёмка камерой прямо из приложения, обрезка и поворот, сжатие.
- PDF и другие файлы: загрузка, просмотр в приложении.
- Ссылки: URL на Google Диск, Яндекс Диск, сайты.
- Кнопка «Конспект к этой паре» на карточке текущей пары — привязка автоматически.
- Поиск по названиям и тексту конспектов; распознавание текста на фото (OCR) — этап 3.

**Литература.** Список источников по предмету: автор, название, тип (учебник / статья / сайт), файл или ссылка, обязательная или дополнительная, статус (прочитать / читаю / прочитано). Из источника одной кнопкой создаётся задание «прочитать главы 3–5».

**Экзамены и билеты.** Дата экзамена, список вопросов (вставкой текста списком), статус каждого вопроса (не начат / выучен / повторить). По кнопке строится план подготовки: вопросы распределяются по дням до экзамена с днями на повторение.

### 4.2. Задания и разбивка с помощью ИИ

**Создание задания.** Название, предмет, тип (ДЗ, доклад, реферат, лабораторная, курсовая, чтение, подготовка к экзамену), описание (текст, фото, файл), дедлайн (дата и время), важность (обычная / высокая).

**Разбивка.**
1. Кнопка «Разбить на шаги» отправляет в LLM описание, тип, предмет, дедлайн и объём свободного времени до дедлайна.
2. ИИ возвращает список подзадач строго в JSON (схема ниже), каждая — от 15 до 120 минут.
3. Экран проверки: можно менять название и время, удалять, добавлять, переставлять, отмечать зависимости.
4. «Перегенерировать» с комментарием («слишком мелко», «добавь поиск литературы»).
5. «Запланировать» — подзадачи уходят в планировщик (раздел 6). Без подтверждения ничего не попадает в календарь.

Схема ответа ИИ:
```json
{
  "subtasks": [
    {
      "title": "Найти 3 источника по теме",
      "estimate_min": 60,
      "order": 1,
      "depends_on": [],
      "note": "использовать список литературы по предмету"
    }
  ],
  "total_estimate_min": 300,
  "warning": null
}
```
Если времени до дедлайна не хватает, ИИ заполняет `warning`. Ответ валидируется на сервере; при ошибке — один повтор, затем сообщение пользователю.

**Остальное.**
- Прогресс задания = доля выполненных подзадач.
- Шаблоны: сохранить разбивку как шаблон и применять без ИИ.
- Фото задания с доски: ИИ распознаёт текст и заполняет описание и дедлайн, если он есть на фото.
- Учёт фактического времени (таймер на подзадаче) — этап 3, для уточнения оценок.

### 4.3. Календарь

**Виды.** «Сегодня» (главный экран на телефоне), неделя, месяц. Цветовые слои: пары, учёба, личное, отдых, «долгий ящик»; каждый слой можно скрыть.

**Два типа событий.**
- Жёсткие: пары, встречи, всё с фиксированным временем. Планировщик их не двигает.
- Гибкие: подзадачи и дела из ящика. Планировщик может их переносить, если они не закреплены вручную (значок-булавка).

**Действия с событием:** перетащить, изменить длительность, отметить «сделано», «не сделано», «перенести», открыть связанное задание или предмет.

**Настройки времени.** Когда можно ставить учёбу (например, будни 9:00–22:00, выходные 11:00–19:00), время сна, обед, дорога до университета (буфер до и после пар), максимум учебных часов в день. Все значения пользователь задаёт сам в онбординге и меняет в Настройках; приложение только предлагает стартовые.

**Экспорт.** Синхронизация с Google и Яндекс Календарём не нужна.

### 4.4. «Долгий ящик» — отложенные дела

Добавление одной строкой из приложения или бота. Необязательные поля: категория (быт, здоровье, документы, покупки, личное), примерное время (15 мин / 1 ч / полдня), желаемый срок («до конца месяца»), условие («только в будни днём», «нужен ноутбук», «в городе»).

**Попадание в график.**
- Еженедельный разбор (по умолчанию воскресенье, 19:00): приложение предлагает 1–3 дела на неделю и ставит их в свободные окна с учётом условий. Пользователь подтверждает.
- Чем дольше дело лежит, тем выше его приоритет; дела с желаемым сроком идут первыми.
- Кнопка «У меня есть N минут» — показывает подходящее по времени дело.
- Дело можно отметить «неактуально» — оно уходит в архив.

### 4.5. Личное и отдых

- Регулярные личные блоки: спорт, встречи, дорога. Работают как жёсткие события.
- Постоянного графика у работы нет: она идёт как задания со сроком (раздел 4.9).
- Отдых — защищённый блок: планировщик туда ничего не ставит.
- Настройка «минимум отдыха в неделю» (например, один свободный вечер и полдня в выходные). Если план его съедает, приложение предупреждает.
- Привычки (вода, чтение, спорт) как простые ежедневные галочки — этап 3.
- Общий календарь с мужем: видеть его занятость и общие планы — этап 3.

### 4.6. Напоминания

Каналы: Web Push на телефон и Telegram. Для каждого типа напоминания выбирается канал (или оба).

| Напоминание | Когда (по умолчанию) | Содержание |
|---|---|---|
| Утренняя сводка | 8:00 | пары с аудиториями, план на день, дедлайны недели |
| Перед парой | за 15 мин | предмет, аудитория, что взять или подготовить |
| Начало подзадачи | в момент начала | что сделать, ссылка на задание |
| Дедлайн | за 3 дня, за 1 день, утром в день сдачи | задание и прогресс в процентах |
| Вечерний разбор | 21:30 | что не сделано — перенести? |
| Еженедельный разбор | воскресенье, 19:00 | итоги недели и дела из ящика на следующую |

Требования:
- Все времена и смещения настраиваются.
- Кнопки в Telegram: «Сделано», «Отложить на 15 мин», «Перенести на завтра». В пуше — те же действия там, где их поддерживает платформа (Android); на iPhone пуш открывает нужный экран.
- Тихие часы (по умолчанию 23:00–7:30): ничего не приходит.
- Если несколько напоминаний совпали по времени, они склеиваются в одно сообщение.
- Напоминания пересчитываются при любом изменении плана.

### 4.7. Telegram-бот

- `/today`, `/week` — план на сегодня и неделю.
- `/add <текст>` — дело в «долгий ящик».
- `/free` — что можно сделать прямо сейчас.
- Свободный текст («сдать реферат по климатологии до 15 октября») — ИИ распознаёт задание, предмет и дедлайн и присылает карточку с кнопками «Создать и разбить» / «Изменить».
- Пересланное сообщение или фото задания — то же самое.
- Бот отвечает только привязанному аккаунту (проверка Telegram user id).

### 4.8. Категории задач и логичное время

У каждой задачи есть категория (что это за дело) и тип действия (когда его уместно делать). Планировщик ставит задачу только в допустимое для её типа время: написать научному руководителю — в рабочее время до 19:00, а ДЗ — хоть поздно ночью.

**Категории:** Учёба · Работа · Быт · Личное. Список можно дополнять. Категория задаёт цвет и иконку в календаре и фильтр.

**Типы действий и время по умолчанию:**

| Тип действия | Примеры | Когда можно ставить |
|---|---|---|
| Связь с людьми | письмо научному руководителю, вопрос преподавателю, сообщение старосте | будни 9:00–19:00 |
| Учреждения | деканат, библиотека, врач, МФЦ, банк | часы работы места (задаются у дела), по умолчанию будни 10:00–18:00 |
| Самостоятельная учёба | ДЗ, чтение, реферат, подготовка к экзамену | любое время, кроме сна; поздний вечер и ночь разрешены до заданного времени (по умолчанию 01:00) |
| Вне дома | магазин, аптека, забрать посылку | 9:00–21:00; лучше в дни пар, по дороге |
| Домашние дела | уборка, стирка, готовка | 8:00–22:00 |
| Личное | спорт, встречи, хобби | в заданные блоки, вечера и выходные |

Правила:
1. Тип действия задаётся у каждой подзадачи, а не только у задания: в курсовой «согласовать тему с научруком» — связь с людьми, а «написать главу 1» — самостоятельная учёба.
2. ИИ определяет категорию и тип по тексту («написать научруку» → Учёба, связь с людьми) и возвращает поле `action_type` для каждой подзадачи; пользователь может поменять.
3. Время по умолчанию для каждого типа меняется в Настройках; у конкретной задачи можно задать своё окно («только до 17:00», «не раньше 12:00», «только в четверг»).
4. Окно типа важнее общих рабочих часов: самостоятельную учёбу можно ставить позже обычного конца дня, а связь с людьми — нельзя после 19:00, даже если вечер свободен.
5. Дедлайн считается с учётом окна: если письмо научруку нужно отправить до пятницы, последний возможный слот — пятница до 19:00, и предупреждение приходит заранее.
6. Напоминания тоже уважают окно: «написать научруку» не напоминается в 22:00 — напоминание переносится на следующее утро.

### 4.9. Долгие проекты и задания с работы

Проект — большая цель на месяцы вперёд с этапами, например ВКР или поступление в магистратуру. Функция обязательная: базовая версия — в этапе 1, умные функции — в этапе 2.

**Проект (этап 1):**
- Поля: название, категория, итоговый дедлайн (защита, подача документов), описание, контакты (научный руководитель), ссылки и файлы.
- Этапы проекта (вехи): название, дата, статус. Пример для ВКР: тема согласована → обзор литературы → данные и расчёты → главы → предзащита → защита. Даты задаёт пользователь.
- Внутри этапа — обычные задания и подзадачи (раздел 4.2).
- Карточка проекта: этапы, задания, прогресс, конспекты, литература, файлы.
- Регулярные письма или встречи с научным руководителем — повторяющиеся задачи типа «связь с людьми».

**Проект (этап 2):**
- Норма времени в неделю (например, «на ВКР — N часов»): планировщик резервирует её в свободных окнах, даже если близких дедлайнов нет. Число задаёт пользователь.
- ИИ предлагает этапы и даты по описанию проекта и итоговому дедлайну; пользователь правит и подтверждает.
- Таймлайн проекта: этапы на шкале месяцев, отметка «сегодня», отставание подсвечивается.

**Задания с работы.** Постоянного графика нет: задание выдают, срок — 2 недели. Работа становится дипломом, поэтому:
- Кнопка «Задание с работы»: название, описание, файлы, дата выдачи; дедлайн по умолчанию — дата выдачи + 14 дней (можно поменять).
- Категория «Работа»; по умолчанию задание привязано к проекту ВКР (можно отвязать).
- Разбивка ИИ и автопланирование — как у обычных заданий.
- Результаты (файлы, заметки) остаются в проекте ВКР, чтобы потом использовать их в тексте диплома.

### 4.10. Статистика

Этап 3. Показывает, куда уходит время, и помогает реалистичнее планировать.
- За неделю и месяц: часы по категориям, предметам и проектам.
- План и факт: сколько блоков запланировано, сделано, пропущено; сколько заданий сдано в срок.
- Проекты: сколько часов вложено за неделю по сравнению с нормой.
- Факт времени = длительность блоков, отмеченных «сделано»; уточняется таймером.
- Короткая сводка — в еженедельном разборе; графики простые: столбцы по дням, доли по категориям.

### 4.11. Материалы: Яндекс Диск, литература и файлы для ИИ

Все материалы — конспекты, файлы с Яндекс Диска, статьи и учебники — складываются в одну базу знаний по предметам и проектам. ИИ опирается на неё, когда разбивает задания и помогает их выполнять, и указывает, откуда взята информация.

Откуда берутся материалы:
- **Яндекс Диск.** Подключение через Яндекс ID (OAuth). Папку на Диске можно привязать к предмету или проекту. Файлы из неё индексируются автоматически (раз в сутки и по кнопке «Обновить»), копировать их вручную не нужно.
- **Загруженные файлы.** PDF, DOCX, фото — к конспекту, источнику литературы, заданию или проекту.
- **Список литературы.** У источника может быть файл, файл на Яндекс Диске или открытая ссылка (статья на сайте, PDF в интернете) — тогда текст подтягивается и индексируется. Если указано только название книги без файла, текст получить нельзя: приложение отметит источник как «нет текста» и предложит приложить файл.
- **Конспекты в приложении** — тоже часть базы.

Что ИИ делает с материалами:
1. При разбивке задания находит связанные фрагменты по предмету или проекту, и подзадачи ссылаются на них: «прочитать гл. 3 учебника X, с. 45–60», «взять данные из статьи Y».
2. На карточке задания показывает блок «Материалы по теме» — найденные фрагменты со ссылкой на файл и страницу.
3. «Спросить у материалов»: вопрос по предмету или проекту → ответ только по базе, со ссылками на источники. Если в базе ответа нет, ИИ так и говорит.
4. Помощь в выполнении: план доклада или реферата, конспект главы, список вопросов для самопроверки — на основе выбранных источников.

Технически:
- Яндекс Диск — через REST API Диска (чтение файлов и папок, только доступ на чтение).
- Извлечение текста: PDF и DOCX — библиотеками, сканы и фото — OCR (LLM с распознаванием изображений или Tesseract).
- Текст режется на фрагменты, для них считаются эмбеддинги и хранятся в PostgreSQL (pgvector). Поиск — по смыслу и по словам, в пределах предмета или проекта.
- Индексация идёт в воркере в фоне; статус у каждого файла: «в очереди / готов / ошибка / нет текста».
- Ограничения: размер файла до 100 МБ, для книг — постраничная индексация; повторный файл определяется по хешу и не индексируется второй раз.
- Запросы с фрагментами из материалов длиннее обычных, поэтому стоят примерно в 2–3 раза дороже; оценку бюджета в разделе 10 держать с запасом.

Этапы: загрузка файлов и ссылки — этап 1; подключение Яндекс Диска, индексация и материалы в разбивке заданий — этап 2; «Спросить у материалов» и помощь в выполнении — этап 3.

## 5. Модель данных

Ключевая сущность — Event (блок в календаре): всё, что видно в календаре, — это Event со ссылкой на источник (пару, подзадачу, дело из ящика и т. д.). Время хранится в UTC, показывается в часовом поясе пользователя (Europe/Moscow).

| Сущность | Основные поля | Связи |
|---|---|---|
| User | email, password_hash, tg_user_id, timezone, settings (JSON: рабочие часы, сон, тихие часы, лимит учёбы в день, настройки напоминаний) | — |
| Semester | start, end, session_start, session_end, first_week_parity | → User |
| DayOff | date, note | → Semester |
| BellSchedule | pair_number, start_time, end_time | → Semester |
| Subject | name, short_name, color, teachers, control_type, links[] | → Semester |
| ClassRule (пара) | weekday, pair_number, type, building, room, parity (all / odd / even), valid_from, valid_to | → Subject |
| ClassException | date, kind (cancel / move / change), new_start, new_room, note | → ClassRule |
| Note (конспект) | title, kind (text / photo / file / link), body_md, url, class_date | → Subject |
| Attachment | storage_key, mime, size, page_order | → Note, Source, Task |
| Source (литература) | author, title, kind, url, required, status | → Subject |
| Exam | datetime, room | → Subject |
| ExamQuestion | number, text, status | → Exam |
| Task (задание) | title, type, description, deadline, priority, status | → Subject (необяз.) |
| Subtask | title, estimate_min, order, depends_on[], status, actual_min | → Task |
| TaskTemplate | title, type, subtasks (JSON) | → User |
| BacklogItem | title, category, estimate_min, desired_by, conditions, status, created_at | → User |
| Event | kind (class / subtask / backlog / personal / rest / exam_prep), source_id, start, end, is_fixed, is_pinned, status (planned / done / missed), rrule | → User |
| Reminder | kind, fire_at, channel, payload, sent_at | → Event или Task |
| PushSubscription | endpoint, p256dh, auth, device_name | → User |
| AiLog | request, response, tokens, created_at | → User |

Решения:
- Пары не хранятся отдельными записями: занятия на нужный период разворачиваются из ClassRule с учётом чётности, праздников и ClassException. *(В `CONTEXT.md` решено иначе: вхождения материализуются в `events`.)*
- Личные повторяющиеся блоки хранятся с правилом повтора (RRULE).
- Удаление мягкое (deleted_at), чтобы можно было отменить действие.

**Категории и время (раздел 4.8):**
- В Task, Subtask и BacklogItem добавляются поля category, action_type и time_window (своё окно, необязательно).
- Новая сущность ActionType: name, default_category, windows (JSON: дни недели + интервалы времени), editable. Заполняется значениями по умолчанию из таблицы в 4.8.
- Новая сущность Category: name, color, icon.

**Проекты (раздел 4.9):**
- Project: title, category, deadline, description, contacts, weekly_norm_min, status.
- Milestone: title, date, status, order → Project.
- В Task добавляются project_id, milestone_id (необязательные) и issued_at (дата выдачи, для заданий с работы).

**Материалы (раздел 4.11):**
- DiskLink: yandex_path, subject_id или project_id, last_synced_at, oauth_token (в зашифрованном виде — в User).
- Document: title, origin (upload / yandex / url), storage_key или yandex_path или url, hash, status, pages, связь с Note, Source, Task или Project.
- Chunk: text, page, embedding (vector) → Document.

## 6. Алгоритм автоматического планирования

> В `CONTEXT.md` решено использовать CP-SAT с жадным fallback.

Для MVP достаточно жадного алгоритма «сначала ближайший дедлайн»; сложная оптимизация (например, OR-Tools) — только если жадный начнёт давать плохие планы.

**Шаг 1. Свободные окна.** На горизонт от сейчас до самого дальнего дедлайна (не больше 60 дней) берём рабочие часы и вычитаем: жёсткие события, сон, обед, отдых, дорогу до и после пар. Окна короче 15 минут отбрасываем.

**Шаг 2. Очередь.** Берём все гибкие незакреплённые невыполненные блоки. Сортировка: дедлайн задания → важность → порядок подзадач и зависимости.

**Шаг 3. Размещение.** Каждую подзадачу ставим в самое раннее окно, где выполняются все правила:
- блок попадает в допустимое время своего типа действия или в своё окно, заданное у задачи (раздел 4.8);
- закончить за 1 день до дедлайна (настраивается);
- зависимости стоят раньше;
- не превышен лимит учебных часов в день;
- не больше 2 подзадач одного задания в день (чтобы чередовать предметы);
- между блоками длиннее 60 минут — перерыв 10 минут.

Если у задачи узкое окно (связь с людьми, учреждения), она размещается раньше гибких задач, чтобы не остаться без подходящего времени.

Если подзадача не влезает целиком, пробуем разрезать её на части не короче 30 минут.

**Шаг 4. Конфликт.** Если не получается уложиться, задание помечается «под угрозой», и приложение предлагает варианты: сократить оценки, расширить рабочие часы в конкретный день, убрать дела из ящика, сдвинуть внутренний срок. Решает пользователь.

**Шаг 5. Ящик.** Дела из «долгого ящика» ставятся после учёбы, только в окна, подходящие под их условия, не больше заданного числа в неделю.

**Перепланирование.** Запускается при новом задании, изменении расписания, невыполненной подзадаче (вечерний разбор) и по кнопке. Дополнительно — ночная задача в 3:00: всё прошедшее и не отмеченное становится missed и переносится.

Правила перепланирования:
- прошлое, выполненное и закреплённое не трогаем;
- перед применением показываем, что изменится («3 блока перенесены, 1 задание под угрозой»), с кнопкой «Отменить»;
- план должен быть стабильным: без необходимости не двигаем блоки на сегодня и завтра.

## 7. Экраны и навигация

На телефоне — нижняя панель из пяти пунктов: Сегодня · Календарь · ＋ · Учёба · Ящик. Центральная «＋» открывает быстрое добавление с выбором: задание, дело в ящик, событие, конспект. На ноутбуке те же разделы в боковом меню.

| Экран | Что на нём |
|---|---|
| Сегодня | текущая и следующая пара с аудиторией, лента дня по времени, отметки «сделано», прогресс дня, ближайшие дедлайны |
| Календарь | день / неделя / месяц, цветовые слои, перетаскивание, кнопка «Перепланировать» |
| Быстрое добавление | одна строка + тип; для задания — дедлайн и кнопка «Разбить на шаги» |
| Проверка разбивки | список подзадач от ИИ, редактирование, «Перегенерировать», «Запланировать» |
| Учёба → список предметов | карточки предметов с цветом, ближайшая пара и дедлайн |
| Карточка предмета | вкладки: Пары · Конспекты · Литература · Задания · Экзамен |
| Конспект | просмотр текста, галереи фото или PDF; добавление страниц камерой |
| Задание | описание, вложения, подзадачи с временем и статусом, прогресс, дедлайн |
| Экзамен | список вопросов со статусами, план подготовки по дням |
| Ящик | список дел, сортировка по «возрасту», кнопка «У меня есть N минут» |
| Разбор недели | итоги, невыполненное, предложения из ящика, подтверждение плана |
| Настройки | семестр, звонки, рабочие часы, сон, отдых, напоминания, Telegram, push |
| Онбординг | мастер: семестр → звонки → предметы → пары → часы → Telegram → push |

Требования к интерфейсу: мобильная вёрстка от ширины 360 px, светлая и тёмная тема, интерфейс на русском, любое частое действие — не больше 2 касаний.

## 8. Нефункциональные требования

- **Скорость:** экран «Сегодня» открывается меньше чем за 1 секунду (из кэша), быстрое добавление сохраняется мгновенно, синхронизация — в фоне.
- **Офлайн:** без интернета видны план на ближайшие 7 дней, расписание и последние конспекты; отметки «сделано» и новые записи копятся локально и отправляются при появлении сети.
- **Надёжность напоминаний:** отклонение от времени — не больше 1 минуты; после перезапуска сервера неотправленные напоминания досылаются.
- **Безопасность:** только HTTPS; файлы закрыты и отдаются по временным подписанным ссылкам; бот отвечает только привязанному Telegram-аккаунту; ключи API — в переменных окружения, не в коде.
- **Резервные копии:** ежедневный дамп БД и файлов, хранение 14 дней, проверка восстановления раз в месяц.
- **Экспорт данных:** выгрузка всего (JSON + файлы в ZIP) одной кнопкой.
- **Стоимость ИИ:** логирование токенов, месячный лимит расходов в настройках, при превышении — предупреждение. Ожидаемый расход и лимит по умолчанию — в разделе 10.
- **Качество кода:** тесты на планировщик (разные расписания и дедлайны) и на разворачивание пар с чётностью; CI со сборкой и тестами; деплой одной командой.

## 9. Этапы разработки

Три этапа; следующий начинается, когда предыдущим уже пользуются каждый день.

ИИ-разбивка и автопланировщик — во втором этапе: сначала в приложении должны лежать расписание и задания. Второй этап желательно закончить до зимней сессии, чтобы план подготовки к экзаменам уже работал.

Приёмка — по сценариям из раздела 2: этап 1 — сценарии 4 и 5 и утренняя сводка без автоплана; этап 2 — сценарии 1, 2, 3, 6, 7, 8.

Перед выбором провайдера проверить, работает ли он и его оплата из России. Цены на 28.09.2026: Anthropic pricing.
