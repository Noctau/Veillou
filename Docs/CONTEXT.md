# Veillou — контекст для ЛЛМ

> Вставляй этот файл в начало каждой сессии. Исходные хотелки заказчицы — `Docs/TZ.md` (это не спецификация: где этот файл и ТЗ расходятся, прав этот файл). План и текущая задача — `Docs/DEV_PLAN.md`.

## Что строим
Личный планировщик учёбы и жизни для одной студентки (4 курс, метеорология, МГУ; телефон Android, плюс ноутбук). Хранит расписание пар, предметы, конспекты, литературу, задания, проекты (ВКР). ИИ дробит задания на подзадачи, планировщик раскладывает их по свободному времени и сам перестраивает план, если что-то не сделано. Напоминания — Web Push (основной канал) + Telegram-бот (ввод и дубль напоминаний).

Принципы (важнее любой фичи):
1. **Ввод за секунды.** Частое действие — ≤ 2 касаний. Пользователь не заполняет то, что можно вывести (категория, тип действия, дата из текста).
2. **План перестраивается сам, но ничего не меняется без подтверждения**, и любое изменение можно отменить.
3. **План должен быть реалистичным:** отдых — жёсткое ограничение, оценки времени калибруются по факту.
4. **Мало шума.** Каждое уведомление должно стоить того, чтобы его прочитать.
5. **Один пользователь сейчас, два потом** → `user_id` во всех таблицах, все запросы фильтруются по нему.

## Стек (зафиксирован)
**Backend:** Python 3.12, uv, FastAPI, Pydantic v2, SQLAlchemy 2.0 async + asyncpg, Alembic, PostgreSQL 16, pytest. Планировщик — OR-Tools CP-SAT. Повторы — `dateutil.rrule`. Даты из текста — `dateparser` (ru) + свои правила. Время — `zoneinfo`. Telegram — aiogram 3. Push — pywebpush (VAPID).
**Frontend:** React + TypeScript + Vite, vite-plugin-pwa, Tailwind + shadcn/ui, TanStack Query, React Router, react-hook-form + zod, date-fns(-tz), FullCalendar, react-markdown + remark-math + rehype-katex. API-клиент — `openapi-typescript` + `openapi-fetch` (типы из OpenAPI бэкенда).
**ИИ:** dev — Ollama на маке; за интерфейсом `LLMProvider`, прод-провайдер выберем позже (смена через `.env`).
**Инфра:** Docker Compose, Caddy (HTTPS), VPS за рубежом (NL/FI/KZ) — Telegram Bot API и внешние API доступны напрямую.

Три процесса из одного пакета: `api`, `worker`, `bot`. Бот и воркер вызывают `services/` напрямую.

## Ключевые решения
- **Время.** В БД только `timestamptz` (UTC). Шаблоны (пары, звонки, окна типов действий) — локальное «настенное» время в TZ юзера (Europe/Moscow). Naive datetime запрещены.
- **Всё в календаре — строка в `events`.** Шаблоны (`ClassRule` + `BellSchedule` + `DayOff` с учётом чётности; RRULE личных блоков) **материализуются** в `events`: пары — на весь семестр, личные повторы — на скользящие 90 дней (ночная джоба). У вхождения есть `template_id`. Если вхождение правили руками (отмена, перенос, другая аудитория), ставится `detached=true`, и регенерация серии его не трогает. К вхождению пары по FK привязываются конспекты и напоминания.
- **Чётность:** неделя, в которую попадает `semester.start`, получает `first_week_parity`, дальше чередуется по ISO-неделям.
- **Жёсткие и гибкие события.** Жёсткие (`is_fixed`: пары, личное, отдых) планировщик не трогает. Гибкие (подзадачи, дела из ящика, подготовка к экзамену) он двигает, если они не `is_pinned`. Ручное перетаскивание ставит pin. Подзадача может быть разрезана на 2 части, тогда у неё 2 события.
- **Планировщик** — `domain/planner/`, чистая функция `solve(PlanInput) -> PlanResult`, без БД. CP-SAT на сетке 15 мин, горизонт ≤ 60 дней. Жёсткие ограничения: свободное время, окна типа действия и задачи, зависимости, лимит учёбы в день, ≤ 2 подзадачи одного задания в день, перерывы, минимум отдыха. Мягкие (целевая функция): раньше дедлайна, приоритет, стабильность (большой штраф за сдвиг блоков на сегодня/завтра, малый — на остальные дни). Что не влезло, получает `at_risk` с причиной. Если солвер не уложился в таймаут, работает жадный fallback.
- **Ревизии плана.** Каждое применение перепланировки создаёт `plan_revision` (diff: moved/added/removed). Порядок: превью → подтверждение → apply. «Отменить» откатывает на предыдущую ревизию.
- **Калибровка.** На «сделано» можно в одно касание выбрать «быстрее / как планировала / дольше» (не обязательно). Отсюда коэффициент по `(task_type, action_type)` (EMA), на него умножаются оценки ИИ.
- **Типы действий** (`ActionType`, у каждого окна по дням недели): связь с людьми, учреждения, самостоятельная учёба, вне дома, домашние, личное. Задаются у **подзадачи**. Окно типа важнее общих рабочих часов, напоминания тоже уважают окно. Категорию и тип выводит ИИ или правила; руками только правят.
- **Условия дел в ящике** — фиксированный набор чипов, без свободного текста: `weekday_daytime`, `on_class_days` (в городе), `needs_laptop`, `institution_hours`.
- **Экзамены** — интервальные повторения (`domain/srs.py`): выучить, потом повторить через 1, 3, 7 дней, обрезая по дате экзамена. Детерминированно, без ИИ. Блоки идут в планировщик.
- **Быстрый ввод.** `domain/quickparse.py` детерминированно и мгновенно достаёт из текста дату, время, «через N дней», предмет по short_name. ИИ подключается фоном, только для разбивки и неоднозначных случаев.
- **ИИ** только через `ai.LLMProvider.complete_json(messages, schema: type[BaseModel], images=None)`. Ответ валидируется Pydantic; при ошибке — 1 ретрай с текстом ошибки. Все вызовы — джобы в воркере: API отдаёт `job_id`, фронт поллит `GET /jobs/{id}`. Каждый вызов пишется в `ai_log`.
- **Фон.** Таблицы `jobs` и `reminders` в Postgres, воркер берёт их через `FOR UPDATE SKIP LOCKED` раз в ~15 с. Без Redis. У напоминания есть `dedupe_key`; после рестарта неотправленное досылается, дубли исключены.
- **Уведомления** идут через `Notifier` с каналами `push` и `telegram`. Действия в пуше (Android): «Сделано», «+15 мин», «На завтра». Тихие часы, склейка совпавших. При любом изменении плана/расписания будущие напоминания затронутых сущностей пересчитываются. По умолчанию включены: сводка 8:00, перед парой −15, дедлайны, вечерний разбор, недельный разбор. «Начало подзадачи» по умолчанию выключено.
- **Файлы** — интерфейс `Storage` (MVP: диск VPS). Отдача только по подписанным ссылкам с TTL. Дубли определяются по sha256.
- **Auth:** email + пароль (argon2), сессия в httpOnly cookie, фронт и `/api` на одном домене. Telegram привязывается через `/start <одноразовый код>`; бот игнорирует чужие `tg_user_id`.
- **PWA:** Web Share Target (Android) — поделиться текстом/фото из любого приложения → быстрое добавление. Офлайн только на чтение (SW + кэш TanStack Query в IndexedDB).
- Все таблицы: `id UUID, user_id, created_at, updated_at, deleted_at` (удаление мягкое).

## Правила для ЛЛМ при написании кода
**Backend**
- Роутер: валидация → сервис → ответ. Логика живёт в `services/` и `domain/`.
- `domain/` не импортирует SQLAlchemy, FastAPI, aiogram; на входе и выходе dataclass'ы. На каждую функцию — pytest-тесты с граничными случаями.
- Любой запрос: `user_id = :me AND deleted_at IS NULL`.
- Меняешь модель → Alembic-миграция в том же коммите. Меняешь API → `make gen-api`.

**Frontend** (пишется ЛЛМ — правила строгие)
- Только библиотеки из стека; новая зависимость — сначала спросить.
- API-типы только из `src/api/schema.d.ts`, руками не писать.
- Серверное состояние — только TanStack Query. Мутации частых действий — optimistic.
- UI — shadcn/ui + Tailwind; без CSS-файлов и inline style. Mobile-first от 360 px, тёмная тема (`class="dark"`), тексты — на русском.
- Фича живёт в `features/<фича>/` (компоненты + хуки `useXxx`); `pages/` только собирают фичи.
- Навигация: нижняя панель «Сегодня · Календарь · ＋ · Учёба · Ящик» (телефон) / сайдбар (≥ 1024 px).
