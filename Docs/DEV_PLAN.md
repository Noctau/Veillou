# Veillou — Dev plan

Формат: **Milestone → задачи на одну сессию с ЛЛМ (1–3 ч)**, у каждой есть DoD. Отмечай `[x]` и коммить план вместе с кодом.
Правило: следующий этап начинается, когда текущим пользуются каждый день. Сценарии приёмки — ТЗ §2.

## ЭТАП 1 — «всё в одном месте и напоминает»
Приёмка: сценарий 4 (карточка предмета), сценарий 5 (пуш перед парой), утренняя сводка (без автоплана), быстрый ввод в ящик из приложения, бота и «Поделиться».

- [x] **M0.1 Монорепо + backend.** uv, FastAPI `/api/v1/health`, pydantic-settings, async engine, Alembic, `docker-compose.dev.yml` (Postgres 16). Makefile: `dev`, `migrate`, `test`, `lint`, `gen-api`.
  DoD: `make dev` → `/health` 200; `make test` зелёный.
- [x] **M0.2 Базовая модель.** Миксин `id/user_id/created_at/updated_at/deleted_at`, `core/time.py` (now_utc, local↔UTC, «настенное время + дата → UTC»), базовый репозиторий (фильтр user_id + soft delete).

- [x] **M0.4 CI.** GitHub Actions: ruff, pytest (Postgres service), `tsc --noEmit`, `vite build`.

### M1. Пользователь, настройки, Telegram

- [x] **M1.4 Бот: каркас + привязка.** aiogram 3 polling, одноразовый код (10 мин), `/start <код>`, middleware: чужие `tg_user_id` игнорируются.

### M2. Расписание (шаблоны → вхождения)
- [x] **M2.1 Модели.** `Semester`, `DayOff`, `BellSchedule`, `Subject`, `ClassRule` + таблица `events` (kind, title, start, end, is_fixed, is_pinned, status, template_type/template_id, detached, source_type/source_id, subject_id, location, color). CRUD.
- [x] **M2.2 `domain/recurrence.py`.** `expand_class_rules(...)` → вхождения (чётность, valid_from/to, DayOff, период сессии без пар); `expand_rrule(...)`. Чистые функции.
  DoD: ≥ 12 тестов: odd/even, первая неделя, «через неделю», праздник, граница семестра, tz.
- [x] **M2.3 Материализация.** Сервис `sync_series(template)`: сверяет будущие не-detached вхождения шаблона по (шаблон, дата) — обновляет на месте, лишние удаляет, недостающие создаёт. Вызывается при изменении ClassRule/BellSchedule/DayOff/Semester. Редактирование вхождения (отмена/перенос/аудитория) → `detached=true`.
  DoD: тест — правка серии не затирает вручную перенесённую пару.
- [x] **M2.4 Фронт: предметы** (карточки, цвет, преподы, форма контроля, ссылки).
- [x] **M2.5 Фронт: сетка недели пар.** Дни × номер пары; клик → пара; «копировать на день / на другую чётность»; переключатель числитель/знаменатель; звонки.

## ЭТАП 2 — «план строится сам»
Приёмка: сценарии 1, 2, 3, 6, 7, 8.

### M8. Планировщик (`domain/planner`, чистый)
- [ ] **M8.1 Вход/выход и сетка.** `PlanInput` (горизонт, сетка 15 мин, жёсткие интервалы, доступность по `ActionType` и `time_window`, блоки с оценкой/дедлайном/приоритетом/зависимостями/splittable, предыдущий план, настройки), `PlanResult` (placements, at_risk[{id, reason}], diff, stats). Функция `available_slots(...)` → `Domain` допустимых стартов для каждого блока.
  DoD: тесты доступности (сон, обед, буфер дороги, окно «будни до 19:00», окно задачи «только чт»).
- [ ] **M8.2 CP-SAT модель — ядро.** Интервал на блок (optional, presence = «размещён»), старт в своём домене, NoOverlap с жёсткими интервалами, зависимости `end_a ≤ start_b`, дедлайн с буфером (жёстко) / поздно (мягко + at_risk), паддинг 10 мин после блоков > 60 мин.
- [ ] **M8.3 Дневные ограничения.** Булевы «блок в день d»; лимит учебных минут/день; ≤ 2 подзадачи одного задания в день; минимум отдыха (N свободных вечеров + полдня в выходные — как запрет гибких блоков в выбранных окнах, выбор окон — переменная).
- [ ] **M8.4 Разрезание.** splittable-блок → две optional-части переменной длины ≥ 30 мин, сумма = оценка, часть 1 до части 2.
- [ ] **M8.5 Целевая функция.** Σ приоритет × время завершения + штраф за непостановку (огромный, × важность) + стабильность (|Δstart| × вес: сегодня/завтра ≫ остальное) + лёгкое предпочтение утра для «связи с людьми». Таймаут 2 с → greedy fallback (EDF, узкие окна первыми).
- [ ] **M8.6 Тест-сьют.** ≥ 25 сценариев + property-тесты (Hypothesis): размещения не пересекают жёсткое, внутри окон, зависимости соблюдены, лимит дня соблюдён. Бенчмарк: 150 блоков × 60 дней < 2 с.

### M9. Планировщик в приложении
- [ ] **M9.1 Сервис replan.** Сбор `PlanInput` из БД (оценки × коэффициент калибровки) → solve → `POST /plan/preview` (diff) → `POST /plan/apply` → `plan_revision` → `POST /plan/undo`.
- [ ] **M9.2 Триггеры.** Новое/изменённое задание, изменение расписания, «не сделано», кнопка; ночная джоба 3:00 (прошедшее неотмеченное → missed → replan превью к утру). После apply — пересчёт напоминаний.
- [ ] **M9.3 UI.** Шторка «3 блока перенесены, 1 задание под угрозой» + «Применить / Отменить»; drag гибкого блока = pin; при at_risk — варианты: урезать оценки, расширить часы в конкретный день, выкинуть дела ящика, сдвинуть внутренний срок.
- [ ] **M9.4 Калибровка.** На «сделано» — необязательный выбор «быстрее / ок / дольше» → EMA-коэффициент по (task_type, action_type), видимый в Настройках.
